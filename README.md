# The Starry Night — Neural Rendering Pipeline

An end-to-end computer-vision pipeline that brings Vincent van Gogh's
*The Starry Night* (1889) alive in the browser:

```
SAM (ViT-B)  ->  five semantic layers     (sky, stars, moon, cypress, village)
MiDaS depth  ->  fused depth map           (neural estimate + SAM layer prior)
RAFT         ->  dense optical flow        (the measured motion of the design)
GLSL         ->  neural WebGL rendering    (layer parallax + brush streaming)
```

Rebuilt from scratch on the architecture defined by the
*VanGogh Paper-Level Neural Preserving Demo* specification: the same
four-stage skeleton (SAM -> depth -> flow -> GLSL), with every
placeholder turned into a working, paper-level implementation.

**Design invariant — *preserves original brush strokes and colors*:**
every semantic layer shares **one** painting texture; layers differ only
by their alpha masks. The renderer can displace pixels and modulate
brightness, but it physically cannot repaint a hue. The canvas keeps the
artwork's true proportions (73.7 × 92.1 cm → 1.2623 : 1) at every window
size.

## What moves

| Element | Animation |
|---|---|
| **The twin whirlpools** | the two great sky swirls rotate like slow pinwheels (46 s / 62 s a turn, opposite directions), centers located automatically by brightness-weighted k-means over the swirl arms |
| **Ten stars + Venus** | every star halo spins around its detected position (14–24 s, alternating directions) and twinkles on its own two-tone phase |
| **The moon** | the radiant halo rotates (~68 s) while the crescent breathes on a ~14 s cycle |
| **The cypress** | the dark flame sways — wide sweeps at the crown, quick tremors among the leaves, steady roots (amplitude ramp from the SAM mask span) |
| **The village** | thirteen window lights flicker in a two-frequency candlelight rhythm over a slow warm swell |
| **All the brushwork** | RAFT-measured flow streams the strokes along the night current; curl noise adds an organic shimmer |
| **Shooting stars** | a meteor crosses the sky once in a while — or click the sky to summon one |
| **The camera** | depth-scaled multi-layer parallax: mouse-driven, with an automatic slow cruise when idle |
| **The soundtrack** | a gentle generative loop (felt piano, warm pads, glass chimes, long reverb) synthesized live by the Web Audio API — no audio files |

## Quickstart

```bash
# 1. Python dependencies (CPU wheels are much smaller)
python3 -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python3 -m pip install -r requirements.txt

# 2. Model weights (~470 MB total, one-time)
bash scripts/download_models.sh

# 3. Run the whole pipeline (SAM ~2-4 min on CPU, then seconds)
python -m inference.run_pipeline

# 4. View the animated painting
cd renderer/web && python3 -m http.server 8000
# open http://localhost:8000
```

The exported `renderer/web/index.html` also works when opened directly
via `file://` — the exporter embeds a base64 copy of the whole scene
(`assets/scene-data.js`, ~1 MB) alongside the individual files.

## How each stage works

### 1. SAM semantic decomposition (`inference/sam_segment.py`)

SAM ViT-B automatic mask generation (48 instance masks on this canvas)
supplies high-quality object boundaries; classical color/geometry
analysis supplies the semantics — which instance is the cypress, which
is the moon. Highlights of the mapping:

- **moon** — brightest warm blob in the upper-right corner; centroid of
  the V>225 core, halo radius from the bright core extent;
- **stars** — the hard part: whirlpool arms, Venus's halo and every star
  halo form *one* connected bright mass. Local maxima of the halo-scale
  brightness map seed an 80-px-disc flood per luminous dome (Voronoi
  seeds + NMS), which recovers **10 of the 13 catalogued elements fully
  automatically** (the reference project hand-curated all 13);
- **twin whirlpools** — brightness-weighted k-means (k=2) over the swirl
  arms gives both rotation centers and radii;
- **cypress** — the tall dark olive-green flame on the left, snapped to
  SAM boundaries;
- **village** — SAM masks below the horizon band (buildings + hills);
- **sky** — the residual background, **texture-filled** behind every
  foreground element (Voronoi nearest-stroke extension), so parallax
  never reveals holes or ghost copies.

Outputs: `output/layers/*.png` (RGBA cut-outs + filled background) and
`output/elements.json` (star list, vortices, moon, windows, cypress
span, layer depth ordering).

### 2. Depth estimation with semantic prior fusion (`inference/depth_estimate.py`)

A monocular network trained on photographs ranks brushstroke luminance
as much as scene geometry, so the neural estimate is fused with the
SAM-derived layer ordering the way paper-level pipelines do:

```
depth = 0.55 * normalize(MiDaS-small) + 0.45 * layer_prior
```

then edge-aware joint-bilateral smoothing keeps layer boundaries crisp
while interiors become parallax planes. The result: sky (0.08) < stars
(0.30) < moon (0.42) < village (0.74) < cypress (1.0) — the
art-historical reading of the composition, anchored by real neural
depth. `--model zoedepth` switches to full ZoeDepth-NK if its 1.3 GB
checkpoint is available.

### 3. RAFT dense optical flow (`inference/optical_flow.py`)

A painting is static, so RAFT has nothing to measure — the pipeline
therefore *synthesizes frame B*: the painting displaced by the designed
animation field (depth-parallax camera drift, whirlpool rotation,
star-halo spin, moon breathing, cypress sway), then runs torchvision's
`raft_small` on the (A, B) pair at 960×760. The estimated dense flow is
the **measured** motion of the composed animation. It is exported as an
8-bit RG texture (±5 px range) that the renderer streams brushwork
along. A sanity probe (uniform 8-px shift) is recovered as 8.00 px by
the same code path.

### 4. WebGL export & neural rendering (`inference/export_web.py`, `renderer/`)

The exporter writes the shared `painting.jpg`, four grayscale alpha
masks, the 8-bit depth map, the RG flow texture, a JSON manifest, and a
single-file embedded `scene-data.js` for offline use.

The renderer is one Three.js full-screen quad. `depth_parallax.frag`
composites the five layers back-to-front, each with its own
depth-scaled parallax, and animates every element (see the table
above); `optical_flow.frag` is the RAFT advection module concatenated
ahead of it. Rotation angles are computed in JavaScript and wrapped to
[0, 2π] so the motion loops forever without precision drift. An
adaptive quality scaler holds a fluid frame rate on any GPU, and
`prefers-reduced-motion` visitors get a calmer animation.

## Lightweight vs. full-fidelity builds

| Stage | Default (lightweight) | Full fidelity |
|---|---|---|
| Segmentation | SAM **vit_b** (375 MB) | SAM vit_h (2.4 GB) — change the checkpoint path in `sam_segment.py` |
| Depth | MiDaS-small v2.1 (86 MB) | ZoeDepth-NK (1.3 GB) — `--depth-model zoedepth` |
| Flow | RAFT-small (3.8 MB) | RAFT-large — `raft_large` in `optical_flow.py` |

Everything runs on CPU; on a 2-core machine the full pipeline takes
about 4–6 minutes (SAM dominates), each stage isolated in its own
subprocess so 4 GB of RAM is enough.

## Deployment

The site is 100 % static — `netlify.toml` publishes `renderer/web`:

1. Push this repository to GitHub.
2. In Netlify: *Add new site → Import an existing project → GitHub*.
3. Build command: *(leave empty)* — publish directory is already set.
4. Or simply drag-and-drop the repository folder at
   <https://app.netlify.com/drop>.

After changing the Python side, re-run `python -m inference.run_pipeline`
to regenerate `renderer/web/assets/` before deploying.
